## Project 边界

Project 隔离模型凭据、Session、文件、复用配置和用量。Project key 不能访问另一个 Project，即使两个 Project 属于同一账户。当前 Alpha 为单所有者模式，尚不支持团队角色、邀请和所有权转移。

## Harness 与配置

直调请求选择支持的 harness、provider、model 和 instructions。Agent 是可选的已保存预设，用于复用指令、工具与环境。选择一种配置来源，不要混合 inline 字段和预设。

运行时包括 Claude Agent SDK、OpenAI Runtime 和 OpenCode。Project 必须配置对应运行时与模型支持的账号。不可用的选择会明确失败，不会静默切换 harness 或模型。

## Session 状态与续接

每个 Session 有独立工作区，不再选择 Agent 类型，新 Session 也不会共享 Agent 机器。Session 固定接纳时的配置，编辑预设只影响新 Session。

成功的 Run 先提交工作文件和原生续接状态，再报告完成。后续输入使用同一个 Session 及其已提交状态，容器回收后也是如此。运行中的进程、socket 和临时凭据不是持久状态。恢复资料缺失时，空工作区或新 Session 不能代替原任务的续接。

正式会话和已用于 API 的 Session 没有循环的闲置期限。归档保留已存状态，永久删除会移除数据。只有 Cloud 调试 Preview 才可能使用明确记录的 30 天闲置策略。存量共享会话和已审阅的只读迁移对象需要单独验证转换，详见 [Session 续接](/docs/zh-Hans/durable-sessions-v2)。

## Thread、Run 与已发布版本

Thread 是持久 Session 在公开 API 中的资源名。Run 是一次执行轮次，包含状态、事件、文件和用量。无关任务创建新 Session，相关追问沿用同一 ID。

v2 直调不需要 Publish。使用预设时，新 Session 读取已保存配置并固定下来。v1 兼容接口继续选择已发布配置，并要求 `userId`。Publish 为这些旧交付流程保存配置快照，不改变已经接纳的 Session。
