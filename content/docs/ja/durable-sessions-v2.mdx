---
title: "v2 の永続セッション"
description: "harness とモデルを直接選び、同じ Session で作業を続けます。"
---

利用前に対象環境の `/api/v2/openapi.json` に Project 作成・アップロードのルートが含まれることを確認してください。
Cloud 本番での提供や、プラットフォーム負担のモデル利用枠を保証するものではありません。
利用前に対象環境の v2 スキーマを確認してください。この候補契約は本番での提供開始を示すものではありません。

**Thread** は永続的な **Session** の公開 API 名です。**Run** は受付時の実行環境とワークスペースで一回の処理を実行します。
v1 の公開済み Agent 向け動作は維持されます。[v1 クイックスタート](/docs/ja/quickstart) も引き続き利用できます。

| 契約 | v1 | v2 |
| --- | --- | --- |
| 実行設定 | API が有効な公開済み/live Agent | harness・モデル・指示の直接指定、または明示的な保存済み Agent プリセット |
| 新しい Thread の識別子 | 空でない `userId` が必須 | 省略可能、応答は `null` |
| 既存 Thread | 受付時の設定を維持 | 受付時の設定を維持 |
| 利用量の記録 | この API にはなし | `GET /threads/{threadId}/usage` |

Project に自分のモデル provider 認証情報を設定し、Project API キーを作成します。
リクエストで harness・provider・モデル・指示を直接選ぶため、Agent の作成や公開は不要です。保存済みの非公開 Agent は任意のプリセットです。
キーをバックエンドに保管し、アプリ自身でユーザーを認証してください。Project キーは他の Project にはアクセスできません。

## 作成と継続

`MOSOO_API_BASE` を検証済み環境の `/api/v2` に設定し、バックエンドで
`MOSOO_PROJECT_ID` と `MOSOO_API_TOKEN` を安全に設定します。input を省略するとモデルを呼ばずに待機中の Thread を作成します。
応答の `thread.id` を `MOSOO_THREAD_ID` として保存し、以降も同じ ID を使用します。

Project で利用可能な harness/provider/model の組み合わせを選びます。例は `openai-runtime` を使用します。Claude Code は `claude-agent-sdk` と利用可能な Anthropic モデル・認証情報を使用します。Session 内では選択を固定します。未対応の組み合わせや利用できない認証情報は `readiness_blocked` となり、別モデルへ切り替えません。直接作成の応答は `agent_id: null` です。

保存済み Agent を再利用する場合は、`configuration` 全体を `{type: "agent", agent_id: "実際の Agent ID"}` に置き換えます。inline フィールドとの混在はできません。既存の `/agents/{agentId}/threads` はプリセット互換入口として残ります。

任意の入力ファイルは Agent なしでアップロードできます：

```bash
curl -X POST "$MOSOO_API_BASE/projects/$MOSOO_PROJECT_ID/files" \
  -H "Authorization: Bearer $MOSOO_API_TOKEN" \
  -F "file=@./input.csv"
```

返された `file.id` を保存し、作成リクエストに `resources: [{type: "file", file_id: "返された ID"}]` を含めます。ファイルとプリセットは選択した Project に属する必要があります。CLI ログインは所有する Project を明示的に選択できます。Project キーはその Project に限定されます。

```bash
curl -X POST "$MOSOO_API_BASE/projects/$MOSOO_PROJECT_ID/threads" \
  -H "Authorization: Bearer $MOSOO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: durable-create-1" \
  -d '{"configuration":{"type":"inline","harness":"openai-runtime","provider":"openai","model":"gpt-5.6-luna","instructions":"Use tools to analyze files and preserve working state for follow-up."}}'
```

```bash
curl -X POST "$MOSOO_API_BASE/threads/$MOSOO_THREAD_ID/events" \
  -H "Authorization: Bearer $MOSOO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: durable-turn-1" \
  -d '{"events":[{"type":"user_message","text":"Read the inputs and write outputs/report.md."}]}'
```

```bash
curl "$MOSOO_API_BASE/threads/$MOSOO_THREAD_ID" \
  -H "Authorization: Bearer $MOSOO_API_TOKEN"
curl "$MOSOO_API_BASE/threads/$MOSOO_THREAD_ID/files" \
  -H "Authorization: Bearer $MOSOO_API_TOKEN"
curl "$MOSOO_API_BASE/threads/$MOSOO_THREAD_ID/usage?limit=100" \
  -H "Authorization: Bearer $MOSOO_API_TOKEN"
```

## 復旧、ファイル、利用量

アップロードは必須ではありません。ローカル入力には既存の multipart API を使います。
公開リポジトリでは URL と正確な commit SHA を入力し、環境が許可する場合に Agent がツールで取得できます。
入力を再現できるよう、実際の commit を記録してください。

このガイドが対象とする v2 では、新しく作成した各 Session が独立した実行ワークスペースを持ちます。
保存済み Agent が Pet と表示されていても同じです。これらの新しい Session には以下のチェックポイントと復旧ポリシーが適用されます。
既存の共有 Session は受付時の実行環境とワークスペースを維持し、これらのエンドポイントでは移行されません。

Run が成功するとワークスペースとネイティブ実行環境の継続状態を確定します。
コンテナ回収後は同じ Session が確定済み状態を復元します。復元できなければ明示的に失敗し、
新しい空のワークスペースで継続を装いません。`outputs/` 外のファイルも非公開の状態として保持できます。
失敗やキャンセルは新しい成功チェックポイントになりません。

新しく作成したすべての v2 Session に、最後に成功した Run から 30 日の復旧期間を記録します。Pet と表示された Agent から作成した場合も同じです。
次の成功で更新し、失敗やキャンセルでは更新しません。期限後の新規処理は `readiness_blocked` で拒否されますが、
履歴と確定済みファイルは読めます。このポリシーを持たない既存 Session に期限を後付けしません。
これは実行状態の復旧ポリシーであり、保存ファイルの自動削除を約束するものではありません。
実際に数日経過した後の復旧検証は未完了です。短時間の強制コールドテストでは代替できません。

利用量は ID 順です。`nextCursor` を `after` に渡し、`null` で終了します。
未報告の値は `null` で、ゼロではありません。`reportedCostUsd` は実行環境の推定値であり請求額ではありません。
キャッシュと token の集計前に `usageContract` を確認してください。実行中の観測値は再取得で更新されることがあります。

同一リクエストの再試行では同じ `Idempotency-Key` を使い、新しい処理には新しいキーを使います。
同じキーで内容・指示・モデル・設定元を変更すると競合します。同じ Project を明示する CLI ログインと Project キーは冪等性境界を共有します。コミット後に中断した作成は、プリセットが編集・削除されても元の Session を復元します。同じ Session の並行処理は拒否されるため、現在の Run を待つか中断してください。

CLI では `public-thread-api-v2` を選択します。v1 は `public-thread-api` のままです。
両方でアップロード、待機、transcript を利用できます。更新後は対象環境にログインして v2 を設定します。
ログアウト済みの認証情報が自動復元されることはありません。[v2 API リファレンス](/docs/ja/api-reference-v2)。

上の作成リクエストと同じ JSON を `session.json` に保存します。更新した v2 CLI では Project を明示し、JSON で inline 設定または Agent プリセットを選びます。入力ファイルを添付する場合は、アップロードで返された ID を `resources` に追加します。

```bash
mosoo public-thread-api-v2 files upload --project-id "$MOSOO_PROJECT_ID" --file ./input.csv -o json
mosoo public-thread-api-v2 threads create --project-id "$MOSOO_PROJECT_ID" --file ./session.json -o json
```

このリリースは Project に設定した利用者自身のモデルアカウント（BYOK）を使い、モデル提供元がそのアカウントに課金します。今回のリリースにはターン別の金額上限は含まれません。利用量と推定費用の記録は引き続き利用できます。プラットフォームによるモデル提供、チャージ、商用の従量課金は別の将来スコープであり、今回の Session API リリースの前提ではありません。既存 Cloud Session の移行と、Pet/Cattle の二種類および旧動作の完全な廃止はリリース前の残作業です。
これらのエンドポイントは過去の設定を再構成しません。顧客移行は別途レビューした計画が必要です。
