Project キーから harness を直接呼び出せます。Agent は任意の保存済みプリセットです。[API クイックスタート](/docs/ja/quickstart)から始めてください。公開済み Agent を使う既存の連携には、[v1 クイックスタート](/docs/ja/quickstart-v1)と[v1 リファレンス](/docs/ja/api-reference)を引き続き利用できます。

## 設定元を選択する

inline の `harness`、`provider`、`model`、`instructions`、または `configuration: {type: "agent", agent_id: "Agent ID"}` を指定します。両方を混在させないでください。Session は受付時の設定を固定し、プリセットの編集は新しい Session に反映されます。直接作成した Session は `agent_id: null` を返します。v2 のサマリーは旧 Pet/Cattle の `kind` を含みません。v1 の互換フィールドは残ります。

## 同じ Session を継続する

後続の入力には同じ Thread/Session ID を使います。成功したターンは、完了を報告する前にワークスペースとネイティブ継続状態を確定します。`outputs/` 外のファイルは非公開の作業状態として保持でき、公開 artifact はファイル API で取得します。失敗・キャンセルの結果は変更しません。新しい ID や要約の再送は元のコンテキストの復元ではありません。

正式な Session と API で使用した Session は、非アクティブな期間だけでは期限切れになりません。同じ Session ID に次の入力を送り、受付時の設定と確定済みワークスペース・ネイティブコンテキストを継続します。古いスナップショットに記録された復旧期限は継続を妨げません。

明示的にクリーンアップを有効にした Cloud のデバッグ Preview のみ、メッセージ・Run・ファイルの操作が 30 日間ない場合に削除されることがあります。コンソールへのログインや履歴の閲覧では期間を更新しません。このルールは正式な API Session には適用されません。別途審査された移行対象の古い Session は、履歴と保存済みファイルを残して読み取り専用になる場合があります。完全削除は別の明示的な操作です。

時計を進めたテストや短時間の強制コールドテストは、実際に数日経過した後の継続性を証明しません。移行した既存 Session を利用する前に、対象環境の検証結果を確認してください。

## 互換性とリリース

v1 は公開済み設定と必須の `userId` を維持します。v2 は直接実行または非公開のプリセット、任意の利用者 ID、利用量の記録をサポートします。Thread・Run のリソース名は変わりません。API・CLI・ドキュメントの対応バージョンを使用してください。このガイドは顧客データを移行せず、Cloud 本番への提供を保証するものでもありません。
