## Project の境界

Project はモデル認証情報・Session・ファイル・再利用設定・利用量を分離します。同じアカウントが所有していても、Project キーから別の Project にはアクセスできません。現在の Alpha は単一所有者向けで、チームロール・招待・所有権移転は提供していません。

## Harness と設定

直接実行では、対応する harness・provider・model・instructions を選択します。Agent は指示・ツール・環境を再利用する任意の保存済みプリセットです。inline フィールドとプリセットを混在させず、設定元を一つ選びます。

実行環境には Claude Agent SDK・OpenAI Runtime・OpenCode があります。選択した runtime とモデルが利用できる認証情報を Project に設定してください。利用できない設定は明示的に失敗し、別の harness やモデルへ自動で切り替えません。

## Session の状態と継続

各 Session は独立したワークスペースを持ちます。Agent タイプは選択せず、新しい Session 間で Agent のマシンを共有しません。Session は受付時の設定を保持し、プリセットの編集は新しい Session に適用されます。

成功した Run は完了前に作業ファイルとネイティブ継続状態を確定します。コンテナ回収後も同じ Session と確定済み状態を使用します。実行中のプロセス・socket・一時認証情報は永続状態ではありません。復旧状態がない場合、空のワークスペースや新しい Session は元の作業の継続にはなりません。

正式な Session と API で使用した Session には、繰り返し適用される非アクティブ期限はありません。archive は状態を保持し、完全削除はデータを削除します。Cloud デバッグ Preview のみ、明示的な 30 日ルールを使用できます。既存の共有 Session と審査済みの読み取り専用移行対象には、個別に検証された移行が必要です。[Session の継続](/docs/ja/durable-sessions-v2)を参照してください。

## Thread・Run・公開バージョン

Thread は永続 Session の公開 API リソース名です。Run は状態・イベント・ファイル・利用量を持つ一つのターンです。別の作業には新しい Session を作成し、続きの作業には同じ ID を使います。

v2 の直接実行には Publish は不要です。保存済みプリセットを使う新しい Session は、その設定を読み込み固定します。v1 互換 API は公開済み設定と必須の `userId` を維持します。Publish は旧提供フロー用の設定を保存し、既存 Session は変更しません。
